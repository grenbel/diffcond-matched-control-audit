# Reproducibility Notes

This document covers (a) reproducing the numerical results of the main
paper and the supplementary material from the released artefacts, and
(b) running the full Stage-3 cross-backbone pipeline from scratch
(~99 GPU-hours total: ~82 for the initial 3-seed pipeline + ~17 for the
seed-45 follow-up). The paper and its reviews are on OpenReview:
https://openreview.net/forum?id=cpe5PHAgoQ.

**Before anything that imports `models/`:** run
`python third_party/fetch_odgnet.py` (see `third_party/ODGNET.md`).
`models/__init__.py` imports ODGNet's `models/pointnet.py` and
`models/UpTrans.py`, which this repository does not include because
ODGNet states no licence.

Framework-dependent (assume an installed PoinTr environment, i.e. the
publicly available upstream `yuxumin/PoinTr` repository at commit
`3f98676aeaabd9c1150dd04cd0a51f504949ab9c` plus the compiled

- `tools/eval_dtr.py`
- `tools/eval_vanilla_subset.py`
- `tools/eval_predictor_calibration.py`

**Training pipeline files** (drop-in replacements for the corresponding
upstream files; required to reproduce the matched-control training runs):
- `tools/runner.py` -- extends upstream `tools/runner.py` with the DiffCond
  training/validation hooks: aligned per-difficulty validation, DiffCond
  oracle/predict inference paths, PCN proxy-difficulty guard, and
  per-batch integer crop pipeline (the `training_crop_mode='diffcond'`
  branch) shared by DiffCond and the matched-vanilla control.
- `tools/builder.py` -- extends upstream `tools/builder.py` with the
  warm-start remap for DiffCond (`query_ranking -> s_base`, zero-init of
  the DiffCond-specific layers; symmetric remap for UpTrans-DiffCond).
- `datasets/PCNDataset.py` -- extends upstream PCN loader with the
  per-sample proxy-difficulty lookup used by the PCN sanity check.
- `datasets/{ShapeNet55Dataset,build,__init__,data_transforms,io}.py` --
  upstream files vendored unchanged (apart from one header comment line
  in `data_transforms.py`) so the dataset registry resolves consistently
  against this repository's `cfgs/`.
- `utils/parser.py` -- upstream argument parser plus the option
  `--difficulty_source {oracle,predict}` (default `oracle`), which picks
  the oracle or the predicted difficulty label when a DiffCond model is
  evaluated.
- `models/pointnet.py` and `models/UpTrans.py` -- PointNet++
  set-abstraction, up-transformer and dictionary-former building blocks
  and the UpTrans model, required by `models/UpTrans_DiffCond.py`; from
  the ODGNet authors' public implementation (Cai et al., AAAI 2024), not
  part of the upstream PoinTr commit. ODGNet states no licence, so they
  are not included: `python third_party/fetch_odgnet.py` downloads both
  at ODGNet commit `032bca98f89cc3ea4733b331ff91468df1bea0f9`, applies
  our five-line change to `models/UpTrans.py` and checks both files
  against the ones used in our runs (`third_party/ODGNET.md`).
  `models/pointnet.py` depends on `pointnet2_ops`.

The stand-alone scripts can be run directly from this repository
(e.g. `python tools/aggregate_results.py --help`). The
framework-dependent scripts and the training pipeline files must be
dropped into a PoinTr clone (upstream commit
`3f98676aeaabd9c1150dd04cd0a51f504949ab9c`) with this repository's
`cfgs/`, `models/`, `tools/`, `datasets/`, `utils/`, `experiments/` and
`third_party/` overlaid, and with the two ODGNet files fetched, before
they will run.

## Reproduce numerical results in main paper

### SN55 cross-backbone SMH aggregate (main Sec. 5.5 Table 4)

The 9-cell paired-seed analysis cited by main Sec. 5.5 is fully reproducible
from the per-seed eval summaries (n=4 cross-backbone, df=3):
```bash
cd /path/to/repo
python tools/aggregate_results.py
# -> produces data/results/sn55_paired_results.{json,tsv}
# Default --seeds 42,43,44,45 (n=4 cross-backbone)

python tools/paired_stats.py
# -> produces data/results/paired_analysis.tsv (n_seeds auto-detected; df=n-1; t_crit=3.18 at df=3)
# -> prints CDL2 + F-Score paired-seed CI summary
```

The script reads from `experiments/UpTrans*/ShapeNet55_models/*_seed{42,43,44,45}/smh_results/eval_{easy,median,hard}_summary.txt` (**24 files** = 4 seeds x 2 families x 3 modes).
The JSON+TSV in `data/results/` are the deterministic output of running
these scripts on those 24 shipped summaries; the UpTrans checkpoint
binaries themselves were not retained (see the Reproducibility Statement).
The UpTrans training and evaluation logs are in
`logs/remote_archive_20260501/train_logs/` and
`logs/remote_archive_20260501/eval_logs/`.

Expected paired-CDL2 row (Hard, the focal cell): paired mean
$+1.79\%$, $95\%$ CI $[-2.72\%, +6.29\%]$, df=3, $t_{0.975}=3.18$.

### PCN sanity check (supplementary Sec. 5)

The PCN per-seed values in supplementary Table 11 are released as
`data/results/pcn_sanity_results.json` (per-seed F-Score / CD-L1 /
CD-L2 for Vanilla-FT and DiffCond Oracle, seeds 42 and 43, plus mean
and delta-percent). The per-epoch training logs are in
`logs/remote_archive_20260501/train_logs/`
(`train_b1_{vanilla,diffcond}_pcn_seed{42,43}.log`); the values can
also be regenerated by re-running the PCN training pipeline against the
released `cfgs/PCN_models/` configs and looking for
`[Validation] EPOCH: 30` in the run output.

The PCN runs read a float32 `.npy` copy of the PCN point clouds, written
next to the official `.pcd` files. `cfgs/PCN_models/UpTrans.yaml` and
`cfgs/PCN_models/UpTrans_DiffCond.yaml` therefore take their dataset
paths from `cfgs/dataset_configs/PCN_npy.yaml`, which gives the
configuration the runs logged. To write the copy (needs Open3D and
NumPy; `--dry-run` only counts the files):
```bash
python tools/cache_pcn_to_npy.py --data-root data/PCN --category-file data/PCN/PCN.json
```
To read the `.pcd` files directly instead, use
`cfgs/dataset_configs/PCN.yaml` as the `_base_` of those two
configurations; the point clouds are the same up to float32 rounding of
the coordinates.

The difficulty proxy referenced in main Sec. 5.5 PCN sanity check:
```
data/PCN/difficulty_proxy.json (231,792 train + 1,200 test entries)
```
is computed once from the PCN training set; the construction script
lives in `tools/compute_pcn_proxy_difficulty.py`.

### Added-seed ablation matrix (main Sec. 5.3 Table 3)

The three-seed ablation matrix (v1-lambda0 and v2b at seeds 43 and 44,
paired with the seed-42 cells retained in `data/results/all_results.json`)
is regenerated from the provenance record in strict mode:
```bash
python tools/gap_a_results.py   --all-results data/results/all_results.json   --logs "data/results/gap_a_provenance/eval_logs/*.log"   --train-logs "data/results/gap_a_provenance/train_logs/*.log"   --meta-dir data/results/gap_a_provenance/meta   --out data/results/gap_a_results.json
```
Strict mode verifies every digest in the chain (evaluation log <-> sidecar
<-> M2 seal; training log and checkpoint <-> M1 seal; warm-start
checkpoint <-> pinned digest) and aborts on any mismatch. Expected Mean
row for full DiffCond: -4.56% [-5.90, -3.22] (df=2, t=4.30); CE-removal
contrast +1.14pp [-13.91, +16.19]. See
`data/results/gap_a_provenance/README.md`.

### Crop-path quantification (main Sec. 3.3)

```bash
python tools/crop_path_quantification.py --out data/results/crop_path_quantification.json
```
The analytic fields (exact under the ideal continuous-uniform sampler
model) are the values quoted in main Sec. 3.3; the simulated fields are a
Monte Carlo sanity check (seed 2026, 50,000 batches of 48).

## Run Stage-3 from scratch (full GPU pipeline)

[!] Resource: ~82 GPU-hours for the original 3-seed pipeline + ~17
GPU-hours for the seed 45 follow-up (~99 GPU-hours total) on a single
RTX 5090 (32 GB VRAM). Approximate budget breakdown:

Initial 3-seed pipeline (Phases 1--5):
- Phase 1 (SN55 Vanilla 3 seeds): 19h13m
- Phase 2 (SN55 DiffCond 3 seeds): 19h13m
- Phase 3 (SN55 SMH eval, 6 ckpts x 3 modes = 18 evals): 12h49m
- Phase 4 (PCN Vanilla 2 seeds): 15h20m
- Phase 5 (PCN DiffCond 2 seeds): 15h18m

Seed 45 follow-up (added as a one-step extension after the initial 3-seed run, under the pre-specified stop-rule):
- SN55 Vanilla seed 45 (30 ep): ~6h25m
- SN55 DiffCond seed 45 (30 ep): ~6h25m
- SN55 SMH eval (2 ckpts x 3 modes = 6 evals): ~4h12m

### Python environment

The recorded stack of the added-seed runs (exact package list in
`data/results/gap_a_provenance/meta/gap_a_env_manifest.json`) is
Python 3.12.3, `torch 2.8.0+cu128` (CUDA 12.8, cuDNN 9.10.2) on an
RTX 5090 (Blackwell, `TORCH_CUDA_ARCH_LIST=12.0`); Blackwell GPUs need
a PyTorch build for CUDA 12.8 (PyTorch >= 2.7). The earlier runs also
used RTX 5090 instances. Other GPU classes work with the matching CUDA
build of PyTorch; timing will scale.

```bash
conda create -n pointr_repro python=3.12 -y
conda activate pointr_repro

# PyTorch built for CUDA 12.8 (required for RTX 5090 / Blackwell):
pip install torch==2.8.0 torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128

pip install -r requirements.txt   # project dependencies, versions pinned from the recorded environment
```

### Build the CUDA extensions

`models/__init__.py` registers every model module, so the two ODGNet
files must have been fetched (`python third_party/fetch_odgnet.py`) and
all of the following must be built before `python main.py` (or any
`import models.X`) succeeds:

- the five upstream PoinTr extensions under `extensions/`:
  `chamfer_dist`, `emd`, `gridding`, `gridding_loss`,
  `cubic_feature_sampling` (the last three are pulled in by GRNet);
- `pointnet2_ops` from `erikwijmans/Pointnet2_PyTorch` at commit
  `b5ceb6d9ca0467ea34beb81023f96ee82228f626` (directory
  `pointnet2_ops_lib/`), used by AdaPoinTr, SnowflakeNet and
  `models/pointnet.py`. Its `setup.py` hard-codes a
  `TORCH_CUDA_ARCH_LIST` that starts at compute capability 3.7, which
  CUDA 12.8 rejects; set that line to your GPU's capability (12.0 for
  RTX 5090) before building, as the added-seed runs did.

```bash
# From repo root (this repository overlaid on the upstream clone)
python third_party/fetch_odgnet.py   # ODGNet's pointnet.py and UpTrans.py, see third_party/ODGNET.md

for ext in chamfer_dist emd gridding gridding_loss cubic_feature_sampling; do
    (cd extensions/$ext && rm -rf build *.egg-info && pip install --no-build-isolation .)
done

git clone https://github.com/erikwijmans/Pointnet2_PyTorch.git ../Pointnet2_PyTorch
git -C ../Pointnet2_PyTorch checkout b5ceb6d9ca0467ea34beb81023f96ee82228f626
# edit ../Pointnet2_PyTorch/pointnet2_ops_lib/setup.py: TORCH_CUDA_ARCH_LIST -> "12.0" (RTX 5090)
pip install --no-build-isolation ../Pointnet2_PyTorch/pointnet2_ops_lib

# Verify install (imports the whole model registry)
python -c "import models.AdaPoinTr, models.AdaPoinTr_DiffCond, models.UpTrans, models.UpTrans_DiffCond; import pointnet2_ops; print('OK')"
```

If a build fails: confirm `nvcc --version` matches the CUDA build of
your PyTorch (12.8 for the recorded stack) and keep
`--no-build-isolation` so the extension compiles against the installed
torch.

### Re-running the full training pipeline

This repository ships the patched training pipeline (`tools/runner.py`,
`tools/builder.py`, `datasets/`, `utils/parser.py`) on top of upstream PoinTr commit
`3f98676aeaabd9c1150dd04cd0a51f504949ab9c`. After overlaying this
repository onto a fresh `yuxumin/PoinTr` clone, fetching the two ODGNet
files and installing the CUDA extensions, a single matched-control run
is launched via the standard PoinTr `main.py` entry point. Example for
AdaPoinTr Vanilla-FT seed 42:

```bash
python main.py \
    --config cfgs/ShapeNet55_models/AdaPoinTr_baseline_smoke30_diffcrop.yaml \
    --exp_name vanilla_seed42 \
    --seed 42 \
    --val_freq 10 \
    --start_ckpts <path-to>/baseline_300ep/ckpt-best.pth
```

The warm-start file is the Baseline checkpoint `baseline_300ep/ckpt-best.pth`
of the Hugging Face repository linked from `README.md` (SHA-256
`f1acb03baa1f80c5c4eeb361d9b23a0193e9891d31df1a0de0b4de37bee534b3`);
the alternative is to retrain the Baseline from scratch, as described in
the paper's Reproducibility Statement.

The matched DiffCond candidate uses the same command with
`cfgs/ShapeNet55_models/AdaPoinTr_DiffCond_smoke30.yaml`; the
`training_crop_mode: diffcond` field in both YAML files routes both
candidates through the same DiffCond crop pipeline (per-batch
integer-crop + FPS to 2048), matching the shared crop-pipeline
principle of Sec. 3.4 of the main paper.

UpTrans cross-backbone runs swap the config to
`cfgs/ShapeNet55_models/UpTrans.yaml` and
`cfgs/ShapeNet55_models/UpTrans_DiffCond.yaml`; PCN sanity-check runs
to `cfgs/PCN_models/UpTrans{,_DiffCond}.yaml` (the DiffCond PCN run
additionally requires `data/PCN/difficulty_proxy.json`, computed once
by `tools/compute_pcn_proxy_difficulty.py`).

The UpTrans runs do not start from the AdaPoinTr Baseline. Both UpTrans
families warm-start from the 400-epoch pretrained UpTrans checkpoint of the
corresponding dataset released by the ODGNet authors (`pretrained.zip`,
linked under "Pretrained Models" in the `corecai163/ODGNet` repository
README): `ShapeNet55_models/ckpt-best.pth` for ShapeNet-55 and
`PCN_models/ckpt-best.pth` for PCN, passed via `--start_ckpts` as in the
launch comment of each YAML. We used these released files without
retraining; their SHA-256 digests are
`7125cacfae033548a8b274f919a754c06e209d87cb450c5f17dcc9bb9b1165ac`
(ShapeNet-55) and
`803cf872fbb9932a617985691c1138c2e561216cb2d4c62ddf572cc53f0ed3ee` (PCN).
Pretraining UpTrans for 400 epochs with the ODGNet configuration is an
alternative but yields a different warm-start.

The full matched-control sweep over seeds {42, 43, 44, 45} produces in total:
- 12 final checkpoints under `experiments/{UpTrans,UpTrans_DiffCond}/{ShapeNet55,PCN}_models/*_seed*/ckpt-epoch-030.pth` (8 ShapeNet-55: 2 families x 4 seeds; 4 PCN: 2 families x 2 seeds)
- 24 SMH eval summaries under `experiments/UpTrans*/ShapeNet55_models/*_seed*/smh_results/eval_*_summary.txt` (4 seeds x 2 families x 3 modes)
- Aggregate JSON+TSV under `data/results/` (re-aggregate with
  `python tools/aggregate_results.py`)

Of these, the initial three-seed pipeline produced 10 checkpoints and 18
summaries; the seed-45 follow-up added 2 checkpoints and 6 summaries
(same directory pattern with the `seed45` suffix). Re-aggregate with the
n=4 command above to update
`data/results/sn55_paired_results.{json,tsv}` and `data/results/paired_analysis.tsv`.

### Evaluating a checkpoint on the S/M/H bins

```bash
python main.py --test --deterministic \
    --config cfgs/ShapeNet55_models/AdaPoinTr_DiffCond_smoke30.yaml \
    --ckpts <path-to>/diffcond_full/seed42/ckpt-epoch-030.pth \
    --mode hard \
    --exp_name eval_diffcond_seed42_hard
```

`--mode easy`, `median` and `hard` evaluate the Simple, Moderate and
Hard bins of the official ShapeNet-55 test protocol (8 fixed viewpoints
per object). Pass the configuration listed for the checkpoint in
`README.md`. A DiffCond model is conditioned on the bin's oracle
difficulty label by default; `--difficulty_source predict` conditions
the AdaPoinTr DiffCond model on the label of its own difficulty
predictor instead (the UpTrans port supports the oracle label only).
The added-seed evaluations used `--deterministic` as above; some
earlier evaluations ran without it. The ShapeNet-55 data go under
`data/ShapeNet55-34/`, as described in upstream PoinTr's `DATASET.md`.

### Validation

After the pipeline completes, the values in
`data/results/sn55_paired_results.json` should match the released file
within floating-point tolerance (per-seed metrics are pinned to 3
decimals in the upstream summary files).

## Troubleshooting

- **"No module named 'models.UpTrans'" or "'models.pointnet'"**: run
  `python third_party/fetch_odgnet.py` from the repository root.
- **"chamfer_dist not built / ImportError"**: Re-run the extension
  install commands above with the correct CUDA toolkit on PATH.
- **"CUDA out of memory" during Phase 4-5 PCN**: PCN is the most
  memory-heavy phase (`N_POINTS=16384`, `total_bs=16`); reduce
  `total_bs` in `cfgs/PCN_models/UpTrans*.yaml` if running on
  <32 GB cards (RTX 5090 holds the default fine).
- **Numbers don't match released JSON within float tolerance**: most
  likely a CUDA non-determinism (e.g. different cuDNN heuristics
  across drivers). Set `torch.use_deterministic_algorithms(True)`
  and `CUBLAS_WORKSPACE_CONFIG=:16:8` for stricter reproducibility,
  but expect a 5-10% slowdown.
